TL;DR

Spec Kit Agents is a multi-agent, spec-driven development workflow that augments GitHub's Spec Kit with two phase-scoped context-grounding hooks: a read-only discovery prober before each phase, and a validator that runs post-phase repo checks. The two halves of an end-to-end feature task run through a state-machine orchestrator that hands intermediate artifacts (SPEC.md, PLAN.md, TASKS.md) to a separate developer agent.

Hooks ground each stage in concrete repository evidence — existing logging formats, installed dependencies, file paths referenced in PLAN.md — instead of falling back on generic priors. The combined configuration (Full-Augmented) improves judged quality by +0.15 over the unhooked Full pipeline (p < 0.05, Wilcoxon signed-rank) and reaches 58.2% Pass@1 on SWE-bench Lite, beating prior SOTA (SWE-Agent, 56.7%).

Overview

Spec-driven development (SDD) externalizes intermediate artifacts — a spec, an implementation plan, an executable task checklist — so that the agent's intent is auditable rather than implicit. GitHub's Spec Kit operationalizes this as a staged workflow (Specify → Plan → Tasks → Implement).

In practice, this structure does not eliminate a failure mode we refer to as context blindness: the agent's intermediate artifacts can be internally coherent and incompatible with the repository as it exists — hallucinated APIs, missing file paths, unsupported dependencies. These errors compound: when discovered late, the agent backtracks, revises earlier artifacts, or introduces additional inconsistencies.

Spec Kit Agents injects explicit, phase-scoped context-grounding into the same workflow: a read-only prober gathers repository evidence before each phase, and a validator runs repo checks after each phase. The hooks operate on explicit artifacts (SPEC.md, PLAN.md, TASKS.md) rather than being embedded inside the developer's main prompt.

The hook layer

Pre-phase discovery hooks run read-only probing (grep, git, glob, pytest invocations) to surface conventions, APIs, and module structure. Post-phase validation hooks run structural and referential checks against the artifact just produced.

The orchestrator

A state machine routes work between the PM Agent (analysis + version-control inspection, read-only) and the Developer Agent (edits + executions). Human checkpoints gate plan approval; everything else runs autonomously end-to-end.

We evaluate four configurations spanning a continuum of structure: Baseline (no intermediate artifacts), Augmented (Baseline + hooks), Full (Spec Kit workflow only), and Full-Augmented (Full + hooks). All four are evaluated on the same 32 feature tasks across five OSS repositories; quality is judged independently by Claude Opus 4.6 on a 1–5 composite of completeness, correctness, style, and maintainability.

Method: Phase-Scoped Context-Grounding

The core contribution is a context-grounding hook layer that wraps the staged Spec Kit workflow at workflow boundaries. Hooks are first-class agents that operate on explicit artifacts (SPEC.md, PLAN.md, TASKS.md, plus pre-implementation cross-references) rather than being absorbed into the developer's prompt.

Discovery hooks (pre-phase grounding)

Before each phase, a read-only prober gathers evidence about the codebase using repository inspection tools (grep, git, glob). The goal is to surface project-specific conventions, existing APIs, and relevant modules so that subsequent generation is conditioned on concrete, localized context rather than generic priors. For example, for persistence-related features, discovery can identify existing logging formats or storage abstractions and steer the agent away from introducing unsupported dependencies.

Validation hooks (post-phase checks)

After each phase, a validator checks the generated artifact for internal consistency and repository compatibility. For earlier artifacts, validation focuses on structural and referential constraints — do the file paths referenced in PLAN.md exist? are the required libraries present? is the task list feasible and properly ordered? After implementation, validation executes repository checks (unit tests, linters) to detect regressions. This design front-loads error detection by catching hallucinated paths, missing dependencies, or infeasible plans before downstream code generation compounds them.

Tool access control

Hooks validate each phase by probing the codebase before and after reasoning steps, ensuring specifications are grounded in existing project conventions and plans are verified against installed dependencies. The PM agent is restricted to repository analysis and version-control inspection; the developer agent is permitted to edit files and run repository commands required to implement features. Discovery hooks are read-only, while validation hooks extend discovery permissions with execution privileges for project checks (pytest, ruff, and JavaScript test runners) when applicable.

Separation of generation from evaluation. Spec Kit Agents executes the agentic workflow (PM and developer agents) through Claude Code CLI (MiniMax-M2.5 backbone) routed to an Anthropic-compatible endpoint. Quality is evaluated independently using Claude Opus 4.6 on a 1–5 composite of completeness, correctness, style, and maintainability; the composite score is the mean of these dimensions. This separation reduces self-evaluation bias by isolating scoring from the agent's prompts and tool access.

Experimental Setup

We evaluate Spec Kit Agents on 32 feature tasks across five open-source repositories: FastAPI and Airflow (Python); Dexter and Strapi (TypeScript); Plausible Analytics (Elixir with supporting JavaScript). The task set spans multiple change types including API additions, configuration changes, new modules, refactors, and test updates. Each task is run under all four configurations.

  • Baseline / Augmented: 40-minute end-to-end budget; the developer agent skips intermediate artifacts (Augmented adds hooks).
  • Full / Full-Augmented: 90-minute end-to-end budget; the full Spec Kit workflow produces artifacts before implementation (Full-Augmented adds hooks).

Quality is judged by an independent Claude Opus 4.6 rating on a 1–5 scale across completeness, correctness, style, and maintainability. The composite score is their mean. We additionally conduct a blinded human preference study on a subset of tasks to ground the LLM-based evaluation. For statistical comparisons, we treat each feature task as a paired subject across conditions and use the Wilcoxon signed-rank test.

Main Results

Within the 90-minute workflow family, Full-Augmented achieves the strongest overall quality (3.66 vs. 3.51 for Full, +0.15 relative). On the paired subset of completed tasks this difference is statistically significant (Wilcoxon signed-rank, p < 0.05). Gains appear across repositories, with the strongest improvements on FastAPI and Plausible. Repository-level test compatibility remains at 99.7–100% across all configurations — the quality gains do not come at the expense of breaking existing project behavior.

Ablations & SWE-bench Lite

Phase-level hook components

To isolate the contribution of each hook, we evaluate partial configurations relative to the Full baseline (3.51). Both partial variants improve over Full, with Validation-only outperforming Discovery-only; the combined design (Full-Augmented) achieves the strongest result, indicating that the two components are complementary.

Latency vs. quality

Context-grounding hooks add only modest overhead in the 40-minute family (Baseline and Augmented share a 40-min budget), but a larger cost in the 90-minute family due to the longer workflow and repeated hook executions. We therefore view latency as a quality-runtime trade-off.

SWE-bench Lite generalization

Beyond the custom repository tasks, we evaluate Spec Kit Agents on SWE-bench Lite, a benchmark of 300 real-world software engineering issues. Spec Kit Agents achieves a 56.5% pass rate in the Baseline configuration and 58.2% with context-grounding hooks enabled (+1.7% over baseline), placing it ahead of prior published systems under their original setups.

Conclusion

We presented Spec Kit Agents, a multi-agent, spec-driven development workflow that augments GitHub's Spec Kit with phase-scoped discovery and validation context-grounding hooks. Across 128 runs covering 32 features, the Full-Augmented configuration achieves the strongest overall quality, indicating that explicit repository-grounded orchestration improves reliability.

The gains are consistent and stem from stronger alignment between the specification, the discovered repository context, and the final implementation. This improvement comes with additional runtime overhead, making the approach most appropriate for higher-risk or high-complexity tasks. Overall, the results support explicit context-grounded orchestration as a practical design principle for more dependable autonomous software engineering.

Future directions include extending the hook layer to additional artifact types (e.g., test plans, deployment manifests), studying the effect of hook placement granularity beyond the four Spec Kit phases, and evaluating the approach on multi-file refactor tasks that span several of the current artifacts.
